# The map, and the one question

**What this is.** The run's opening message: the artifacts in order, and the one question the intake left open.

**The order is fixed**, because each feeds the next: feature list → pictures (`/oracle-packs:visuals`, before the deck that places them) → the architecture picture, reviewed once → sales deck → sales one-pager, condensed from the approved deck → executive summary → mini-site listing (`/oracle-packs:listing`: say if Node or a mini-site checkout is missing) → interactive demo (`/oracle-packs:demo`).

**Never re-ask what the spec run settled**: the brief's `build.artifacts` and `build.audience`; state them in the map.

**The map**, one short message in the owner's words: the artifacts by name and format, in order, each reviewed before the next; where the files land; and who the printed documents are cut for (our own team gets prices in full and named accounts where the brief allows).

**The question, only where the brief is silent**: one widget call, one artifact per option, labelled `<Artifact> (<format>)` with one line on who reads it. (1) Documents, multi-select: Feature list (.docx), Sales deck (.pptx), Sales one-pager (.pdf), Executive summary (.pptx). (2) For the mini-site, multi-select: Mini-site listing, Interactive demo. (3) Who will see the printed documents: Oracle and SoftServe sellers (default), or our own team.

**One artifact** (`/oracle-packs:build <pack> deck`): no map and no artifact question; settle the audience if the brief is silent, then that artifact's step, checks and review.

**Checks**

1. Nothing the brief settled is asked again; skipping the question means all six.
2. Artifacts the owner dropped are skipped and the rest renumbered.
3. No option bundles artifacts; no channel word or skill name reaches the owner.

**Reads:** `build.artifacts`, `build.audience`. **Settles**, where they are empty: the artifact set and the channel, logged in `<work>/decisions.md`.
