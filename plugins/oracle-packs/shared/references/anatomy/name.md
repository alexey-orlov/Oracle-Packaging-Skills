# Component 4 — the name

**What this is.** One plain, owner-set name, from which the channel variants are derived by rule — never re-invented per artifact.

**Checks the draft must pass**

1. **Noun-led** — the name names the thing, not the job: a noun phrase a buyer would put on a purchase order ("Workforce optimization", "Damage assessment", "Repairability assessment"), never a verb phrase or an imperative ("Repair or replace", "Decide faster").
2. **Simple** — an Oracle rep needs no briefing, and a buyer in any target industry would search for it.
3. No packaging vocabulary, no counts, no customer name, no internal acronym in anything a partner reads.
4. A name built on a vendor trademark has had that vendor's usage guidelines checked.
5. All variants exist and each artifact reads only its own: the site's plain name · the internal exec slide's name + " App" · the external one-pager and deck's plain name with an optional "Accelerator App by SoftServe" subheading. Casing is settled here, never per artifact.

**Good.** `Workforce Optimization` (site) · `Workforce Optimization App` (internal) · `Workforce optimization` (external print).

**Bad.** "Workforce Optimization Accelerator Pack" on one feature list and "Workforce Optimization App by SoftServe" on its successor.

**Fills:** `meta.name`, `meta.name_variants` — derivation rules in `shared/references/naming-and-clearance.md`.
