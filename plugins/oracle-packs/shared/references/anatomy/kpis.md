# Component 11 — key performance metrics

**What this is.** **One metric set per pack.** Each metric carries a formula, a baseline, a cleared figure, a figure status, a caveat, and an attribution rule that varies by channel. Two contradicting or overlapping sets for one pack are unacceptable.

**Checks the draft must pass**

1. One set, used by every artifact. The figures never change by channel; only the name attached to them does — under the customer's name where clearance allows for that channel, under the anonymized descriptor otherwise. Clearance is revocable and re-checked every round.
2. Each figure states its status once, in one plain word: proven, measured, modeled, forecast, estimated, in preparation. "Proven" only on a delivered result; proof-of-value figures say "proof of value", and a target is never typeset as an outcome.
3. No number ships without its caveat line.
4. The **end-to-end** figure, not the engine's: thirty minutes including review, not fifteen minutes of solve.
5. Each metric's formula is stated, and computed identically on the before and the after for the same window.
6. A small percentage carries the sentence that says why it is large at scale.

**Good.** *"~30 min to optimize and approve a region's four-week plan: down from ~2 days"* · *"up to +26% productivity gain on proof-of-value data"*, under *"KPIs measured before/after on proof-of-value data; figures are illustrative, not contractual."*

**Bad.** The print artifacts shipping one set and the site a different, modeled one for the same pack.

**Fills:** `kpis[]` — `name`, `formula`, `baseline`, `figure`, `figure_status`, `caveat`, `attribution`.
