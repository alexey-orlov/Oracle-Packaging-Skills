# The sales deck — .pptx, 16:9, ten slides

**Slide order, fixed.** Packs differ in content, never in anatomy. The spec keys per slide are on the deck skill's own `slides-1-5.md` and `slides-6-10.md`.

1. **Cover** — name, one-liner, who it is for, the family's hero picture. No tier line, no running header.
2. **Use case** — problem card | solution card, up to three KPI chips, the anchor line.
3. **Vertical applications** — four equal cards, one concrete line and one picture each.
4. **Today → tomorrow** — the narrative form of the reframe, as a pair of pictures, plus one named vertical case.
5. **Proof** — the one metric set with the channel's attribution and the caveat line.
6. **Why it sells for the partner's seller** — its own slide: cross-sell path, net-new consumption, repeatability.
7. **Solution layers** — the vendor ladder with the value arrow.
8. **Architecture** — the data flow: sources → the app → the engine on the named infrastructure, labelled arrows.
9. **Service packages** — the tier table.
10. **Service packages, detailed** — the same rows with prose in every cell.

**The components, in the form they take here.** Name → the cover title plus the running header on every content slide. One-liner → the cover subtitle, short form. ICP → the cover's lower line. Verticals → slide 3. Problem ↔ solution → slides 2 and 4. Capabilities → the capability-handling rows on slides 9 and 10. Workflow → slide 4, prose. Architecture → slide 8, canonical detailed form; its ladder is slide 7. Oracle products → named on the architecture, every integration claim stating its tier. KPIs → slide 5. Packages → slides 9 and 10.

Speaker notes in the source decks carry live review comments and are never reproduced.
