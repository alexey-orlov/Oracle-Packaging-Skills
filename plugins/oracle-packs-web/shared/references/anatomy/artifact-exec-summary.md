# The executive summary — one slide, in the host deck's style

Built to paste into someone else's deck, on that deck's own master.

**Six blocks, two rows by three.** Top: use case · solution layers · proof of value. Bottom: service packages · capabilities · planned next steps. The footnote: price footnote, metric caveat only where figures print, divergence sentence (alone when a full sentence, run into "Pack scope differs…" when a fragment). Internal contact block.

**The components here.** Name → the title. One-liner → the subtitle. Problem ↔ solution → one card, solution first, the problem as one trailing sentence. Verticals → names on one sub-line. Architecture → the ladder (a stack, not a flow) from the application layer down, as on the deck; anything above it is not a rung. Required products → the rungs. KPIs → three stats, business metrics only; a header naming the customer is the attribution, else one anonymous line; not cleared here → an empty panel, never half filled; no figure yet → the metric's name in label type, never figure type, over one line, "To be measured in the proof of value; results to follow." Technical criteria ride the PoV tier's scope as "Proof accepted when …". Packages → three tier rows (name · scope · price · duration); a missing value is one grey label-sized line, never price type. Capabilities → areas and categories, as many as the panel holds. Next steps → three numbered items. ICP, workflow and optional products are absent by design.

**Standing rules.** One slide. No new visual language: the host deck's shapes, colours and existing diagram. The speaker notes name the cut (internal: prices shown come off before external use; external: prices or none) and where the customer may be named.
