# The feature list — .docx, one A4 page

**Section order, fixed**

1. The mini-site lockup: the SoftServe wordmark, a hairline rule, `Oracle AI & Data Solutions`.
2. H1 — the internal name variant + " — Feature list".
3. Two intro lines: the approved one-liner (`one_liner.full`, or `feature_list.intro`), then `For ` + `icp.line`. Nothing else — no kicker, no eyebrow, no `App.` definition label.
4. The capability matrix — `Area | Category | Features | Current status | Standard customization scope`, plus an optional `Tier first available`. Area, Category, status and scope merge down across their rows. Footnote markers append inline to the feature name.
5. Legend, one line: `●` available · `◐` partial · `○` roadmap, all three set in one symbol face so they are the same size.
6. Footnotes — the caveat alone, at most three, 15 words or fewer each. **No page footer**: the spec version and the build date live in the file's properties.

**The components, in the form they take here.** Name → the H1. One-liner → the first intro line. ICP → the "For …" line. Capabilities → the matrix, and this document is their master. Workflow → partial, as the review-and-approval area. Oracle products → integration rows, each with its own status. KPI **names** may appear as an area of the matrix; KPI **values**, the problem ↔ solution, the architecture and the packages are absent by design.

**One A4 page is a requirement.** The build estimates the height and walks a fit ladder, and verifies the real page count where Pages is installed. A tree that fits no rung is not built: the limit lands on the capability tree (`shared/references/anatomy/capabilities.md`), never on the type size.

**No pricing, ever.**
